1. Scope and operator

enterprise-test is an internal social media management application used by authorized company personnel to manage the company's own Facebook Pages through the Facebook Graph API. This policy covers information processed by that application, including information about people who interact with those Pages. It also describes the accompanying static legal website.

The operator responsible for this processing is [TO BE COMPLETED: company legal name, business address and privacy contact]. The application is not offered for public account registration.

2. Information processed

  • Internal user and session information: employee name, email address, role, account assignments, active status, password hash and session records.
  • Facebook authorization information: OAuth authorization codes during exchange, authorization state, the IDs and names of authorized Pages, and Page access tokens. When several Pages are available, their IDs, names and tokens are temporarily stored together for Page selection. After selection, the selected Page token is stored.
  • Page content and interactions: Page profile information and follower count; post IDs, text, publication times and links; comment IDs, related post IDs, commenter display names when returned by Meta, comment text and times. The API response cache can also contain fields returned by Meta, including commenter IDs if present in the returned author object.
  • Internal work records: drafts, uploaded images and videos, labels, schedules, review decisions, comment assignments, internal notes, replies and their delivery status.
  • Metrics and operational records: likes, comment and share counts, follower snapshots, manually entered or imported metrics, API usage records, synchronization and publishing jobs, errors and audit events identifying internal actors and actions.

The current Facebook integration reads recent posts and top-level comments and supports publishing Page posts and replying to comments. It does not implement live Facebook Messenger message reading or sending. Direct-message records supported in the test interface are sandbox records. Data entered manually may include additional information supplied by internal users.

3. Why information is used

Information is used to authenticate internal users, authorize access to selected Pages, prepare and review content, publish approved content, schedule work, handle Page comments, display performance metrics, and troubleshoot or audit application operations. A cache reduces repeated API requests.

4. Facebook permissions and authorization

An administrator initiates Facebook authorization and chooses an authorized Page where necessary. The default code requests pages_show_list, pages_read_engagement, pages_manage_posts, pages_read_user_content and pages_manage_engagement to list Pages, read Page content and engagement, publish content, read user comments and reply to comments. If Facebook Login for Business is configured, the permissions come from that configuration instead.
